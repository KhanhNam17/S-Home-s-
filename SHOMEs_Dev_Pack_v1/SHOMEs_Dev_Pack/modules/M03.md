# M03 — Chủ trọ, tin đăng và ảnh

## FE
OWN-01 dashboard, OWN-02 list, OWN-03/04 wizard4 bước, OWN-06 profile.
Dashboard đếm theo API; list có status moderation và availability riêng, filter/search/pagination. Hành động theo trạng thái: draft/rejected/hidden có gửi duyệt; approved sửa phải cảnh báo chuyển pending.
Wizard: basic → location/amenities → phí → ảnh/preview. Lưu draft không đòi đầy đủ; submit focus lỗi đầu. Upload từng ảnh, reorder array, imageIds[0] là cover.
Giữ expectedVersion từ lần đọc; không auto refetch ghi đè dirty form. Xung đột giữ input và thông báo có bản mới.
Phí có input nullable + “Miễn phí”/“Chưa rõ”; không để input trống tự thành0.

## BE
ListingService luôn ownerId=session.user.id; reject extra ownerId/status. Draft nullable; submit/full approved-edit validate toàn bộ dữ liệu merge.
Upload assets trước, attach imageIds trong PATCH transaction. Asset phải owned/ready/chưa gắn tin khác; không nhận URL tùy ý.
PATCH approved→pending, pending→pending với bản mới; giữ reason cho rejected/hidden cho tới submit. Availability mutation riêng không đổi moderation.
Profile publicPhone hợp lệ để submit; displayName 2–100. API errors không lộ tin owner khác.
Bảng: users/profile/listings/media_assets/listing_images/moderation_events.

## API
GET/PATCH /owner/profile; GET /owner/dashboard; GET/POST /owner/listings; GET/PATCH /owner/listings/:id; POST /:id/submit; PATCH /:id/availability; POST /owner/uploads; DELETE /owner/uploads/:id; GET /media/:id.
Form fields/ranges và transition dùng 02, không định nghĩa lại.

## Trình tự lưu gửi
Create draft một lần →upload assets →PATCH với version →nếu status draft/rejected/hidden thì POST submit với version vừa trả →pending.
Nếu PATCH approved đã thành pending, dừng; không gọi submit lần hai.
Nếu submit fail ảnh/phone/field →tin giữ state trước submit, owner sửa tiếp.
